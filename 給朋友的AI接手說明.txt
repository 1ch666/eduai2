【P1：核心體驗與真正 AI NPC，需分清前後端】

後端權限：不需要。資料風險：低；勿加入外部分析或上傳私人輸入。

P1-2 真正 NPC AI 對話（需要後端管理者處理）
問題：ScriptedNpcDialogue 是固定備用台詞，沒有 AI 呼叫。現有 court 程序 speaker API 不等於自由 NPC 聊天。
位置：court-game/NPC-IMPLEMENTATION.md 接口提案；src/court.ts、court-rules.ts；Unity WorkerDialogueProvider 與網頁橋接。
做法：管理者確認新增 NPC messages 端點；先實作 owner、CSRF、角色／階段、NPC 案件歸屬、version、requestId 冪等、長度與限流，才接 AI。只提供角色可知事實；不得改證物或案件事實，不能讓證人知道全案答案。
Unity 只傳非秘密場次 ID／問題，同源網頁處理 session 與 CSRF；金鑰、cookie、token 不進 Unity／PlayerPrefs／前端永久儲存。
驗收：未登入、跨帳號、重送、跳階段、逾時、無額度、惡意提示詞、切換 NPC 都有測試；明示 ai／scripted，失敗不偽裝成功。
後端權限：需要正式 API／模型開關／Secret 管理者；不可自行部署或換 key。
資料風險：私人對話、雲端存檔、模型費用；限免費已確認模型，日誌不記完整私人對話，保留舊資料。

P1-3 Docker 與接手包同步
位置：court-game/Dockerfile、Dockerfile.dockerignore、compose.yaml、docker/nginx.conf、.github/workflows/court-docker.yml。
問題：白名單已補 auth-sync.js，但本批尚未重建映像。
做法：遊戲 build 確定後再 build/run Docker，測 /play/、/court/、靜態依賴；記來源 commit、映像識別、成品校驗值與新手操作。
驗收：容器不配置正式後端時明示 API 501／功能不可用；不能說容器已附登入或 AI。
後端權限：本機靜態容器不需要；遠端發布依既有權限，不開付費 runner。
資料風險：勿將 .env、憑證、正式資料或本機 Logs 打包。

【P2：案件多樣性、雲端恢復與回饋】
P2-1 不重複案件生成（需要後端管理者處理）
位置：src/court.ts、court-rules.ts；NPC-IMPLEMENTATION.md 的 cases/generate 提案。
問題：目前獨立遊戲仍是固定平板案；模型匯入不會自動變成新案件。
做法：先定版本化 JSON schema，包含程序、人物、行為／審理年齡、固定事實、證物、時間線、角色知識與法規來源；伺服器驗證合法組合及事實一致性後保存。以近期案件 fingerprint＋相似度檢查降低重複，有限重試，失敗改核准範本；不能承諾永遠不重複或無限生成。
驗收：不能只改姓名算新案；少年旁觀產品限制、強制法律協助、缺來源法條、矛盾證物、惡意輸入與額度耗盡均有測試。
後端權限：需要；正式法律來源／生效／沿革須查官方資料。
資料風險：AI 幻覺、法律誤導與成本；標示教育模擬、非法律意見。

P2-2 雲端對話摘要、恢復與庭後回饋（需要後端管理者處理）
位置：CourtRoom 儲存／court API、Unity provider、NpcDialogueUI.cs。
問題：現況只保留每 NPC 最近 20 則記憶體訊息，刷新就消失；AI 自由評語不是客觀正確率。
做法：伺服器保存有版本的場次摘要與已確認線索，持久化／migration 先由管理者審核。庭後分開程序、證據與論證，不以勝訴算答對；匯入／自由 AI 評語不計排名。
驗收：刷新／斷線恢復、跨帳號拒絕、重送不重複寫入、舊版本可讀。
後端權限：需要。資料風險：高，禁止 reset migration、刪 DO、清空資料。

【P3：進階角色與效能改善，等 P0～P2 穩定再做】
P3-1 完整多程序角色、發言／證物特寫與動畫
位置：CourtPresentation.cs、NPC/、角色素材與 court 網頁整合。
做法：依民事／刑事／少年合法角色配置人物與鏡頭，法官主持、當事人發聲、代理／辯護及旁觀單步各有 UI；不背景無限生成。素材只用授權清楚免費資源並更新 ASSET-LICENSES.md。
驗收：每角色可完成適用案件，旁觀暫停真的停止生成；模型不要遮擋操作。
後端權限：纯美術不需；程序／AI 規則需管理者。資料風險：模型授權與程序失真。
P3-2 首載／中文字型及低階手機效能
位置：字型、模型匯入設定、WebGL 模板、build 設定。
做法：以實際下載量與記憶體分析決定字型／動畫裁減；動態任意中文不可直接換回僅靜態字集造成缺字。維持桌面控制與手機控制分流。
驗收：比較冷啟動和快取啟動、下載 bytes、記憶體與掉幀，不只報本機 build 時間。
後端權限：不需要。資料風險：低，但過度 stripping 可能使反射／字型／動畫失效。

   index.html、styles.css：首頁、公民小學堂、生活法律問答、筆記預覽、AI 小助理、留言、帳號／紀錄匯入匯出及新工具導覽。
   civics-data.js：舊主站公民課綱內容，32 個單元／32 道靜態題。
   court/index.html、court.js、court.css：案件／角色／年齡／法律協助設定、場次、證物、陳述、語音、角色對話與 Unity iframe。
   practice/index.html、practice.js：新版登入練習、判分、弱點補強入口。
   planner/index.html、planner.js、planner.css：週課表、表單、專注計時、ICS、推播訂閱及音樂入口。
   rankings/index.html、rankings.js：積分榜、個人名次與段位。
   photo/index.html、photo.js：本機照片處理、手動輸入題目文字、文字 AI 講解及本機筆記。
   music-data.js、music-player.js：曲目宣告與播放器；音訊檔沒有提交。
   sw.js、manifest.json：PWA 宣告及收到 push 時顯示通知的 Service Worker。

2. Cloudflare Worker：src/index.ts 路由、capabilities、安全標頭及靜態 assets。
   src/auth.ts、accounts.ts、session.ts：註冊／登入／登出、復原碼、首次取碼、Session、CSRF 與進度。
   src/messages.ts、ai.ts：共用留言、限流與 Ollama 文字 AI；既有 AI 透過 Worker 呼叫 https://ollama.com/api/chat，金鑰只在伺服器。
   src/court.ts、court-rules.ts：六個教學案件、角色限制、程序狀態、保存及角色 AI 台詞。
   src/practice.ts、practice-data.ts：伺服器派題、questionToken、判分、首次作答、弱點與指南。
   src/planner.ts：排程 CRUD、衝突檢查、專注 heartbeat。
   src/push.ts：PushStore 訂閱儲存與 VAPID 公鑰端點，尚無發送鏈路。
   src/rankings.ts：全域累積積分榜，與原需求的週時間榜／正確率榜不同。
   src/photo.ts：已登入者送文字至 Ollama 取得講解，不收照片 bytes。
   src/http.ts、env.ts：共同 HTTP、安全／大小限制、環境型別。

3. Durable Objects SQLite（不是 D1）：
   wrangler.jsonc 宣告 MESSAGE_ROOM/MessageRoom（v1）、ACCOUNT_STORE/AccountStore（v2）、COURT_ROOM/CourtRoom 與 LEARNER/Learner（v3）、PRACTICE/Practice（v4）、PLANNER/Planner（v5）、PUSH_STORE/PushStore（v6）、RANKINGS/Rankings（v7）。
   AccountStore 儲存帳號／session／原進度；Practice、Planner 按使用者，CourtRoom 按場次；PushStore、Rankings 有 global 物件。保留所有既有資料及綁定名稱。repo 宣告 v7 不代表正式帳號已套用，需後端管理者核實。

4. Unity：court-game/，Editor 6000.3.24f1。
   Assets/Scenes/Courtroom.unity：真正 3D 法庭。
   Assets/Scripts/CourtSession.cs：獨立 /play/ 的「消失的平板」固定調查、作答、結束與重玩。
   Assets/Scripts/CourtPresentation.cs：網頁主控模式的座位／全景／走動鏡頭及幾何人物。
   Assets/Scripts/Player/FirstPersonController.cs、Interaction/、UI/、Assets/Plugins/TouchControls.jslib：鍵鼠及手機操作。
   Assets/Scripts/NPC/WorkerDialogueProvider.cs：對話 provider 原始碼，註解仍標記沒有接入 Courtroom.unity；目前網頁 court 的角色 AI 不等於它已接入 NPC。
   Assets/WebGLTemplates/Court/：網頁模板；play/index.html、touch-controls.js、Build/* 是追蹤中的 WebGL 成品。

5. 法律與包裝：
   law-data/manifest.json + 40 個 shard：法務部中央法律／命令快照；scripts/sync-law-data.mjs 為更新腳本。本次沒更新法規。
   scripts/copy-assets.mjs 將主頁、court/photo/play/planner/practice/rankings、SW、manifest、音樂 JS 與 law-data 複製至 .gitignore 的 public/，供 Worker ASSETS 使用；public/ 不是 Git 追蹤來源。
   court-game/Dockerfile、compose.yaml、docker/nginx.conf、.github/workflows/court-docker.yml：靜態遊戲／court 預覽容器；API 明確回 501，不含完整平台後端。不能稱新學習頁已打包。

【三、程式掃描問題與下一步（依優先級，交給朋友實作）】

P0：現有使用／資料可信度

P0-1 登入與正式後端銜接。
證據：index.html 在 github.io 對 Worker 跨站呼叫 auth/progress；src/session.ts 使用 SameSite=Lax；court/court.js 在 Pages 導向 Worker 同源入口。其他新工具也依賴登入。可能出現登入後讀不到 session、需登入功能無法使用。這次沒有重現正式登入，不把某一原因當作已確診。
建議：後端管理者檢查正式 Worker 版本、ASSETS、binding、Session/Cookie、CORS/Origin 與同源入口；前端依確認結果提供清楚入口／錯誤說明，不重做登入。
位置：index.html、src/session.ts、src/http.ts、src/index.ts、新工具的 api helper。需要後端權限：正式處理需要。資料風險：高（帳號／存檔）。

P0-2 Practice 取題洩露解析與限流判斷。
證據：src/practice.ts 的 clientQuestion 只去掉 correct，其他欄位仍含 explanation；取題時已把解題解析送給前端，不能作嚴格公平的競賽題。兩個限流判斷 `if (!practice.allow(...))` 未 await，與其他 DO RPC 呼叫方式不一致，可能只在判斷 Promise 的真值，需修正並驗證實際限流。
建議：檢查取題回傳白名單、RPC await、限流整合測試；修正前不要當作防刷榜已完成。
位置：src/practice.ts 的 clientQuestion、questions／answer handler。需要後端管理者處理；資料風險：中至高（統計／排行／額度）。

P0-3 排名自動公開與首次作答競態。
證據：src/practice.ts 首次作答直接呼叫 rankings.record；src/rankings.ts 公開 top 的暱稱和答題統計，未見自願加入檢查。isFirstAttempt 與 record 是兩次 RPC，需測不同 token 同題並發是否都被算首次；排名更新失敗被 catch 吞掉，缺一致性修復。
建議：管理者先確認 opt-in／退出與統計政策、首次作答原子性／冪等及排名同步補償。不能以現有 token 防重放直接推論並發防刷也完成。
位置：src/practice.ts、src/rankings.ts、rankings/。需要後端權限：是。資料風險：高（公開個人學習行為／公平性）。

P0-4 音樂初始化與無限缺檔輪播。
證據：music-player.js 使用 Number(state.volume) ?? 0.5；全新使用者 state.volume 缺少時 Number(undefined) 是 NaN，?? 不會套用預設，audio.volume 設定可能拋錯。music-data.js 全部用 /music/*.mp3，Pages 會指向網域根路徑而非 /eduai2/music/；git 無音訊檔。error handler 每1.2秒切下一首且無終止條件，全缺檔可能連續 error。
建議：有效數值預設、base-aware URL、缺檔停止／單次提示；補真正授權音源及打包複製規則。樂曲公共領域不代表任一錄音都免費，須核實具體錄音。
位置：music-player.js、music-data.js、scripts/copy-assets.mjs。需要後端權限：前端修正不需要。正式儲存／部署另需管理者安排。資料風險：低，另有授權風險。

P1：已實作功能缺口

P1-1 題庫及弱點補強不足。
29題各屬不同概念，低於每概念至少5題首次作答門檻；重做同題又不列首次統計。需增加各概念多題、難度與題型變化、來源版本、真正不同的補強題。不要只增加新概念各1題。
位置：src/practice-data.ts、src/practice.ts、practice/practice.js；靜態題整理不需正式後端權限，判分／統計變更需後端管理者。資料風險：中。

P1-2 照片功能的名稱／能力及重送、大小限制。
photo/photo.js 的 API body 只有 text 和 requestId；src/photo.ts 明確 ocrAvailable:false，使用文字模型。需選擇增加 OCR/Vision 或改為「照片參照＋手動文字講解」。Canvas 壓縮在品質降至門檻時即使超過2MB也會 resolve，需在輸出後再檢查；requestId 只驗證格式，沒見結果快取／去重，重送可能重複耗用 AI。
位置：photo/index.html、photo/photo.js、src/photo.ts。前端說明與大小處理可做；模型、費用、私隱、API去重需要後端管理者。資料風險：高（題目照片／文字）。本機筆記亦應檢查共用裝置、換帳號隔離。

P1-3 Push capability 過度代表可用。
src/index.ts push:true 只代表訂閱端存在；沒有實際 delivery。planner 的訂閱 UI 不該承諾到點能收到。需由管理者完成 VAPID 私鑰／免費排程方式、通知去重、修改取消、逾期丟棄及失效訂閱；目前先提供誠實狀態與 ICS fallback。
位置：src/index.ts、src/push.ts、sw.js、planner/planner.js。前端文案可做；Secrets、發送、排程及正式驗收需後端。資料風險：中至高。src/push.ts／PLATFORM-STATUS.md「cron 必須付費」缺當前官方方案查核，不能據此購買或升級；讓管理者查核免費選項。

P1-4 排程修改、週重複與專注時間。
src/planner.ts updateSlot 將 startIso/endIso 合入資料後卻以 u.start_iso/u.end_iso 更新 SQL，欄位命名不同可能使修改時間不生效。conflicts/listSlots 依原始時間比較，未見每週 recurrence 的未來實例展開；需核對跨週顯示／衝突。startFocus 可建多筆，endFocus 未先驗證已結束狀態或補算末段離線間隔；planner.js heartbeat 沒用伺服器 elapsed 修正顯示。這些都不能拿來做可信任競賽時間。
建議：管理者核對欄位映射、原子衝突檢查、重複與時區、同帳號單一有效計時、背景／失聯停計、end冪等。
位置：src/planner.ts、planner/planner.js。後端部分需要管理者；UI 時區顯示可本機處理。資料風險：高（課表／時間）。

P1-5 排行與原規格不一致。
src/rankings.ts 是累積 difficulty 積分及固定0/50/150/300/500門檻，沒有每週重置、有效時間榜、首次正確率榜、20題門檻、百分位或不足20人規則。rankOf 只比較 score，top 再比較 correct，同分時名次定義亦需統一。
位置：src/rankings.ts、src/practice.ts、rankings/。建議先明示「累積練習積分榜」，其餘依完整需求逐步做；正式統計及隱私需後端管理者。資料風險：高。
