## 收尾檢查順序

1. 先確認 git status，保留協作者修改，只提交本輪自己的檔案。
2. 集中修正能從程式或實測證明的既有問題；不為湊功能新增後端工作。
3. 修改完成後集中執行相關回歸；發布前由乾淨提交跑既有 CI。
4. 若修改 Unity，須真正 Editor 編譯／Play／Release WebGL，核對成品大小；
   若未修改 Unity，不為文件變更重建遊戲。
5. 若有程式發布，僅發布 eduai2；保留正式資料、Secret、binding、權限與
   免費方案。核對 Worker、Pages、Docker 與同一來源提交後再回報。
6. 實機測試與真正模型品質由使用者協助，缺證據就明確記錄待驗收，不能
   以桌面模擬代替。全部未完成需求留存，下一輪不自動擴大範圍。
