## 截圖回報後修正

CourtTransport／ReplayLoader 的預設 fetch 原先作為類別方法呼叫，會帶錯誤 this。改用包裝函數維持 globalThis receiver，避免瀏覽器原生 fetch 的 Illegal invocation。新增 receiver 回歸測試，與通訊及重播載入共15項通過。仍需真實登入／Unity 場次驗收，不以 mock 證明截圖故障全部排除。

HUD 改用 NpcDialogueUI 序列化引用的完整中文字型，不再隨機取舊 Text 的裁切字型；移到右上方並使用不透明底色。Unity 6000.6.2f1 重新 build exit 0。本機真實瀏覽器使用既有測試帳號恢復版本1場次，伺服器面板顯示已同步；載入新 WebGL 後 HUD 可見「沒有寄出的相機」「陳述與爭點 · 可用操作 1」，無前次缺字。這不是手機或所有角色驗收。

字型修正版 data 15,290,192、wasm 5,847,147、framework 83,191、loader 48,540 bytes，四項 21,269,070；另 touch 5,172。相較前一批四項減少960 bytes，不宣稱已量測首載改善。

## 永久刪除內容

使用者確認刪除後，CourtRoom transaction 清除 state、requests、dialogue、npc_requests、court_events、court_v1_requests。Learner transaction 清除該場次清單與 generated_requests 的案件副本，並清空關聯生成嘗試的設定 payload。不批次刪除既有其他場次。

保留最小刪除識別紀錄防止延遲初始化復活；保留生成請求 ID／時間／限流標記防止藉刪除刷新 AI 額度。不是整個 DO deleteAll，也不保證底層配置容量立即縮小或服務永遠不會滿。網站不提供復原；供應商備份／PITR 依平台保留政策，不宣稱物理備份即刻銷毀。

若跨 DO 第二步清除失敗，API 不回成功，可以同一場次重試；第一步已封鎖存取，不會重新建案。舊軟刪除場次不自動批次清除。發布後只影響新刪除操作及針對指定場次的重試。

本機 SQLite12項與 TypeScript 通過（包含生成副本刪除、其他場次保留、交易失敗回滾）；未用正式帳號執行刪除。同步與刪除功能已部署，來源4600a19，Cloudflare版本9c325640-6a75-45c0-9ed4-8214ffcd5124。字型修正版發布結果另記。
