# 舊場次空法庭相容修正（2026-09-27）

使用者回報：HUD 顯示題庫相機案／陳述與爭點，但場內無人物。程式與記憶體 SQLite 測試確認一條可重現路徑：早期 court_events 的公開 snapshot.npcs 是空陣列；snapshotV1 固定回傳已保存事件，所以即使目前 Worker 已能產生角色，舊場次仍空白。這是已確認的程式缺陷，不代表已讀取使用者正式私人場次確認唯一成因。

## 修正

src/court.ts 的 snapshotV1 在擁有者及 requestId 驗證後，僅對「目前事件無 NPC、目前案件能產生公開角色」補一筆現在的 checkpoint。場次版本增加 1，不改程序、案件、證物、答案、陳述或對話。舊事件原樣保留，不能倒填角色冒充歷史。state 與新事件在同一 transactionSync 寫入；失敗全部回復，重讀不重複增加。

有未完成 v1 NPC 請求時延後補記，避免使進行中回覆過期。一般場次及已有（包括不可見）NPC 的事件不變；已刪除或非本人場次不可修復／讀取。沒有新增表、binding、Wrangler migration、Secret、權限、AI 呼叫或付費服務。

這是一筆可追溯的相容性資料更新，不是「完全沒有資料寫入」。與一般版本更新相同，持有舊版本的操作會被 409 拒絕，須刷新後再操作。現有 100 版本操作上限未改。

## 驗證

scripts/test-court-journal.mjs：實際 Node SQLite 交易、模擬 DO lifecycle。涵蓋舊事件不變、只新增一次、擁有者／請求格式、進度保持、舊版本拒絕、寫入失敗回滾、物件重建、進行中 NPC 不被中斷。這不是 workerd／正式使用者端驗收。發布版本另行記錄。

本次後端修正可以使用既有 play 成品發布，無須等待尚在調整的法袍／坐姿。不能把本機候選 public/play/Build 誤發布；部署前從已提交 play/ 重建 public。
